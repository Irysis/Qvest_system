## 7. ★부수 검거 — 스캐너 거짓 0건 (★원인 진단은 당일 정정됨)

레지스터리 스캐너가 **"유량 의존 팩터 0건"을 두 번** 반환했다. 거짓이었다(실제 51/373).
**증상은 실재했다. 그러나 내가 처음 적은 원인은 틀렸다.**

### 틀린 원래 진단 (철회)

> "R 정규식 `\b` 가 한글 섞인 문자열에서 오류 없이 FALSE 를 반환한다 (TRE·PCRE 둘 다)"

**거짓이다.** 재현 시험(`stage_artifacts/wb_repro/repro2.R`, Write 도구로 작성):

```
패턴 charToRaw: 5c 62 52 65 76 65 6e 75 65 5c 62     ← 5c = 백슬래시, 정상
케이스                fixed   TRE    perl
순수 ASCII            TRUE    TRUE   TRUE
한글 뒤 / 앞 / 사이   TRUE    TRUE   TRUE
기호 포함             TRUE    TRUE   TRUE
경계 없음(XRevenueY)  TRUE    FALSE  FALSE   ← 음성 대조 정상
부재                  FALSE   FALSE  FALSE
```

### 진짜 원인 — 스크립트 작성 경로가 백슬래시를 먹는다

도구 호출로 `cat > x.R <<'RS' ... RS` 를 쓰면 명령 문자열이 **JSON 인코딩**을 거치며
백슬래시 한 겹이 소비된다. `\\b` → `\b` 가 되고 R 은 그것을 정규식 워드경계가 아니라
**백스페이스 문자(0x08)** 로 읽는다 ⇒ "백스페이스+Revenue+백스페이스" 를 찾으므로 **항상 FALSE**.

파일을 열면 즉시 보인다 — 오염판 `repro.R:22` 는 `paste0("\b", p, "\b")` (백슬래시 1개).
**Write 도구로 작성한 파일에는 이 오염이 없다.**

### 살아남는 규약

1. **이스케이프·정규식이 들어가는 스크립트는 heredoc 금지 — Write 도구로 작성.**
   `\n`·`\t`·`\\` 전부 해당한다.
2. 패턴 사용 전 **`charToRaw(pat)` 첫 바이트가 `5c` 인지 실측**. `08` 이면 오염.
3. **검사기의 0 은 결론이 아니라 정지 신호** — 원인을 두 번 오진하는 동안에도
   나를 두 번 다 세운 유일한 규약. 무손상으로 살아남는다.
4. `fixed=TRUE` 는 의도가 리터럴이면 여전히 합리적이나 **이유가 "한글" 이 아니다.**
