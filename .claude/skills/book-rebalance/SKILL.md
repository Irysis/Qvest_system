# BOOK 리밸런싱 (book_id 단위 표준 절차)

**발효**: 2026-08-30 (도훈 지시 — "BOOK 코드별로 리밸런싱 표준화. 각 전략에 필요한
코드와 데이터들이 모두 다를 거잖아").

**해결하는 문제**: 지금까지 리밸은 사람이 기억으로 러너를 호출했다. 그래서 같은 날
세 가지 침묵 결함이 한꺼번에 드러났다 — ①다운로드는 됐는데 적재가 안 돼 컨센서스가
한 달 정지(게이트 둘 다 통과, 20종 중 9종 교체) ②AE 신호 생산자에 호출자가 0건이라
한 달 정지(소비자가 직전 달을 조용히 재사용) ③m4 BOCPD 팔이 271개월 내내 0회 발화.

셋의 공통 기전은 하나다 — **잴 것을 안 재고 재기 쉬운 것을 쟀다.**

## 소관 경계 (도훈 지시 2026-08-30 — 먼저 읽을 것)

| | 소관 | 소유자 |
|---|---|---|
| 데이터 **적재**(QuantiWise·DART·MCP·API) | ✗ 이 스킬 밖 | 데이터 리프레시 — `ensure_data_current.sh` · 신선도 정본 `freshness_audit.R` |
| 그 데이터를 쓴 **리밸런싱 실행·검증·보고** | ✓ 이 스킬 | 본 문서 |

리밸 스킬은 **전제 충족 여부만 재고, 미달이면 중단해 그쪽으로 넘긴다.** 리프레시 명령을
안내하지도, 대신 실행하지도 않는다. 경계를 넘으면 같은 값(신선도 판정)을 두 곳에서
만들게 되고 — 이 저장소가 반복해 데인 계통이다 — 두 곳에서 만든 값은 반드시 갈라진다.

## 원칙 3줄

1. **신선도는 소비면에서 잰다.** 원천 상태파일·mtime·"러너가 OK를 찍었다"는 근거가 아니다.
   실제로 읽히는 파케이의 `max(Date)`를 축마다 따로 잰다 — 한 축이 신선하면 합산 지표는
   신선해 보인다(앵커는 주가 축이 채운다).
2. **미측정은 미달이 아니다.** 부재 = MISSING · 판독불가 = UNREADABLE 로 갈라 보고한다.
   '못 읽음'과 '낡음'이 같은 색이면 다음 사람이 원인을 원천이 아니라 게이트에서 찾는다.
3. **죽은 축은 차단한다.** 오버레이 팔마다 역사 발화율을 센다. `expect_alive` 인데 0회면
   그 팔은 죽은 것이고, **전략 구현이 덜 된 것**이다. 경고로 넘기면 "오버레이가 있다"는
   서술만 남고 실제 보호는 없는 전략이 배포된다(m4 BOCPD 팔 271개월 0회 발화가 그 실례).

## 절차

### 0. 사양 확인

정본 = `02_Infrastructure/book/rebalance_spec.json` (schema `book_rebalance_spec_v1`).
book_id 별로 **러너 · 입력(소비면 경로·신선도 관용·생산자·배선 여부) · 오버레이 팔 ·
사후검증**을 선언한다. 사양에 없는 book_id 는 리밸하지 않는다 — 먼저 사양을 적는다.

> ★사양을 `06_Registry/book/` 에 두지 말 것. 그 폴더는 **등록 정본** 전용이고
> `book_write_guard.sh` 가 writer 경유만 허용한다(등록 자격 검증 우회 차단).

### 1. 사전점검 (필수 — 건너뛰지 않는다)

```bash
.venv_qvest_ml/Scripts/python.exe 02_Infrastructure/book/book_rebalance_preflight.py \
  --book-id BOOK_0001 --as-of 2026-09-01
```

세 축을 잰다. **둘 다 차단축이다.**

| 축 | 재는 것 | 실패 시 |
|---|---|---|
| A | 입력 신선도 — **소비면** `max(Date)` vs as_of 직전 영업일 | STALE/MISSING/UNREADABLE → **BLOCK** + 소관 이관 |
| B | 입력이 러너 산출인가 외부 적재인가 | 표시(이관 대상 식별용) |
| C | 오버레이 팔의 **역사 발화율** | DEAD(0회) / REVIVED(구판 부활) → **BLOCK** |

`GO` 가 아니면 러너를 돌리지 않는다. `--json` 으로 기계 판독.

**축 A 실패 = 데이터 리프레시로 이관.** 여기서 적재하지 않는다. 검사기가 각 입력의
`refresh_owner` 를 찍어 어느 소관인지 알려준다.

**축 C 실패 = 전략 수리.** 죽은 축을 얹은 채 배포하지 않는다. 두 갈래뿐이다 —
①팔을 고쳐 살린다 ②의도적 퇴역이면 사양에서 `expect_alive:false` 로 뒤집어
**회귀 감시**로 전환하고 `note` 에 실측 사유를 남긴다(구판 조건이 되살아나면 REVIVED 로
잡힌다). 검사 출력에서 감시 중인 축은 `[감시]` 로 찍혀 살아 있는 축과 구분된다.
★②는 등급 축 변경이므로 **도훈 승인 사안**이다 — 세션이 임의로 뒤집지 않는다.

### 2. 러너 실행

사양의 `runner.cmd` 를 그대로 쓴다(사전점검 출력 마지막 줄에 찍힌다).
러너는 자체 게이트를 가진다 — BOOK_0001 = Gate A(원천 수신) · Gate B(팩터DB 앵커 내용) ·
Gate D(하드제약·전월 지문). 게이트가 막으면 **사유부터 보고**하고 우회하지 않는다.

### 3. 사후검증

사양 `post_checks` 를 산출물로 재도출한다(러너 로그의 OK 를 인용하지 말 것 — 진술은
증거가 아니다). 최소: Σw=1 · 실질보유 ≤25 · long-only · 유동성 · **비중 지문이 전월과
다를 것**(조용한 재출력 검출) · manifest.as_of 일치.

### 4. BOOK 트래킹 갱신

```r
source("02_Infrastructure/book/book_registry.R")
update_book_tracking("BOOK_0001", list(as_of=..., last_nav_date=..., weights_fingerprint=...,
                                       regime=..., invested=..., cash=..., n_equity=...,
                                       gate_d="PASS", data_vintage="...", artifacts="..."))
```

writer 경유만. `06_Registry/book/**` 직접 편집은 훅이 막는다.

### 5. 텔레그램 — **2통** (비중 + 해설)

`tg_agent_brief(agent="Book", ...)`. 표제 정본 = `qvest-telegram` SKILL §5.6b.

리밸 1회당 **두 통**을 보낸다. 숫자와 해석을 한 통에 섞으면 둘 다 안 읽힌다.

#### 5-1. 확정 비중 — `[BOOK] 트래킹 — {book_id} {월} 확정 비중`

| 섹션 | 내용 |
|---|---|
| summary | 한 줄 결론 (20~100자) |
| kv 현재 리서치 상황 | 단계 · 대상 · 데이터 종점 · 검증 결과 |
| kv 배분 요약 | 국면 · 주식/현금 · 종목수 · 전월 대비 |
| table 종목별 비중 | 2열(종목 · 비중). 표는 2열 상한 — 순위는 행 순서로 |

**데이터 종점**과 **DEAD 오버레이 유무**는 여기 반드시 적는다.

#### 5-2. 배분 해설 — `[BOOK] 코멘트 — {book_id} {월} 배분 해설`

**애널리스트 노트 문체.** 왜 이 배분이 나왔는지를 설명한다.

| 섹션 | 내용 |
|---|---|
| summary | 표면 수치 + **그것을 그대로 읽으면 안 되는 이유** 한 줄 |
| bullet 📖 **용어** | 본문에 나오는 약어를 **한 줄씩 풀이**(MSM·VEA·KTRI·꼬리위험 등) |
| bullet 오버레이 축별 | 축마다 한 섹션. **무엇이 움직였고 무엇이 안 움직였나** |
| bullet 전망·관찰 포인트 | 다음 달 뒤집힐 여지가 있는 지점 |
| bullet 판정의 성격 | 절대 수준인가 상대 순위인가 등 해석 주의점 |

**문체 규약**:
- 기계적 표현 금지. "꺼졌다/걷혔다/안 풀린다" → "경보 문턱을 하향 통과하며 총점에서
  8점이 일괄 제거됐습니다" / "해소된 결과로 보기는 어렵습니다" / "해제는 제한적일 전망입니다"
- **약어는 반드시 용어 섹션에 풀이**한다. 독자가 사전을 찾게 하지 않는다.
- 수치는 **변화의 원인까지** 적는다. "꼬리위험이 −0.354 → −0.514" 로 끝내지 말고
  "그중 −0.134 는 데이터 최신화에 따른 종목 교체 기여분" 까지 간다.
- **움직이지 않은 축도 적는다.** 한 축만 보고하면 "그 축이 원인"으로 읽힌다.

★**넣지 않는 것 — 수리 이력·인프라 작업**(도훈 2026-08-30). 전략 코멘트는 배분 판단을
설명하는 문서다. 결함 수리·배선 변경·검사 결과는 여기 섞지 않는다(필요하면 별건 보고).

#### 5-3. 중복 가드

두 통의 제목이 같은 scope 로 정규화돼 30분 창에서 2통째가 막힐 수 있다
(`BLOCKED duplicate dispatch`). 내용이 다른 별개 메시지이므로 **`force = TRUE` 로 명시
override** 하고 그 사유를 호출부에 주석으로 남긴다 — 가드를 끄지는 않는다.

## 신규 BOOK 등재 시 (사양 작성 규약)

전략마다 코드·데이터가 다르므로, 등재와 **동시에** 사양을 쓴다. 최소 항목:

- `runner`: cmd(플레이스홀더 `{as_of}`·`{as_of_compact}`·`{sig_ym}`) · 산출 경로 · 게이트 목록
- `inputs[]`: **소비면 경로**(생산 원천이 아니라 전략이 실제로 `read_parquet` 하는 파일) ·
  `date_col` · `mode`(`data` 일단위 lag / `decision` as_of 행 존재 / `anchor` sig_date 일치) ·
  `max_lag_days` · `producer` · `produced_by_runner` · `refresh_owner`(적재 소관 — 낡았을 때
  넘길 곳. **리프레시 명령이 아니라 소관 이름**을 적는다)
- `overlays[]`: `panel` · `fire_expr`(pandas eval) · `expect_alive`
  — 죽은 팔을 알면서 두는 경우만 `expect_alive:false` + `note`(실측 사유) 로 회귀 감시 전환
- `post_checks[]`

★신규 전략에 오버레이를 얹을 때는 **얹은 그 라운드에서 발화율을 재라.** 0회면 그 축은
구현된 게 아니다. 이 검사가 있는 이유는 축이 죽은 채로 등재되는 걸 **등재 시점에** 막기
위해서지, 배포 후에 발견하기 위해서가 아니다.

★외부 적재 입력이 이 사양에 새로 들어오면 **데이터 리프레시 쪽 감사 목록에도 등재**한다
(`02_Infrastructure/ops/morning_steps/freshness_audit.R`). 감사 목록에 없으면 아무도 안 잰다 —
2026-08-30 실사고가 정확히 그것이었다(전략 소비 패널 6종이 감사 밖이라 한 달 정지).

`max_lag_days` 는 **실측으로 재단**한다. 두 양을 갈라야 한다 — 원천의 정상 발행지연과
캐시의 낡음은 다르다(FRED 주간계열 정상 7d vs 조기 생성 핀 28~35d → 문턱 14).

## 하지 않는 것

- **데이터 적재** — QuantiWise·DART·MCP·API 어느 것도 이 스킬이 돌리지 않는다.
  낡으면 중단하고 데이터 리프레시로 넘긴다(리프레시 명령 안내도 하지 않는다).
- 사전점검 건너뛰고 러너 직행 · BLOCK 을 무시하고 강행 · 게이트 사유 우회
- 러너 로그의 "OK"를 사후검증으로 인용 · `06_Registry/book/**` 직접 편집
- **DEAD 축을 통과시키기** — 차단축이다. 통과시키려면 고치거나, 도훈 승인 하에
  회귀 감시로 전환하는 두 길뿐이다. `expect_alive` 를 세션 판단으로 뒤집지 않는다.
- 오버레이 문턱 임의 재보정(등급 축 = 도훈 권한)
