# PDF 출력 서식 규칙 (도훈 2026-10-15)

**적용 범위**: Q 가 도훈에게 주는 인쇄 · 열람용 PDF 전부(용어집 · 원페이퍼 · 보고서 · 라운드 보고 사본 등).
**도구(단일 경로)**: `Rscript 00_Lawbook/tools/md_to_print_pdf.R <in.md> [out.pdf] [landscape|portrait]` — 원본은 Markdown 이고 PDF 는 생성물이다(PDF 를 손으로 고치지 않는다 · md 를 고치고 다시 뽑는다).

## 글꼴 — 현대하모니로 통일

| 요소 | 글꼴 | CSS |
|---|---|---|
| 본문(문단 · 목록 · 표 본문) | 현대하모니 **L** | `font-weight: 300` |
| 소제목(h2 · h3 · h4) | 현대하모니 **M** | `font-weight: 500` |
| 굵은 글씨(`**…**` · 표 머리 · 문서 제목 h1) | 현대하모니 **B** | `font-weight: 700` |
| 코드 · 경로 · 식별자(`code` · `pre`) | Consolas(고정폭 — 열 정렬 보존) · 그 안의 한글 = 현대하모니 | `font-family: "Consolas", "HDH"` |

- 글꼴 파일 = 설치본 `%LOCALAPPDATA%\Microsoft\Windows\Fonts\현대하모니+L.ttf · +M.ttf · +B.ttf`(없으면 `%WINDIR%\Fonts`). 도구가 base64 로 HTML 에 **내장**한다 — 설치 패밀리 이름이 제각각(`HDharmony B` · `현대하모니 L` · `HDharmony M`)이라 이름으로 찾지 않는다.
- 글꼴 파일이 없으면 **멈춘다** — 다른 글꼴로 조용히 대체하지 않는다.
- 일반 고정폭 지정(`monospace`)을 글꼴 목록에 넣지 않는다 — 넣으면 코드 안 한글이 굴림체로 떨어진다(10-15 실측).

## 쪽 · 배치

- A4 · 기본 **가로**(넓은 표) — 표가 좁은 문서는 `portrait`.
- 여백 11 · 10 · 12 · 10 mm · 본문 8.8pt · 행간 1.45 · 머리글/바닥글(URL · 날짜) 없음.
- 첫 열(코드)은 줄바꿈 없음.

## 쪽 나눔 — 표 · 내용이 중간에 잘리지 않게(도훈 2026-10-15)

- 도구가 제목(h1~h4)부터 다음 제목 전까지를 한 블록으로 묶고 블록 · 표 · 코드 블록 안 쪽 나눔을 금지한다. 제목만 있는 조각은 다음 블록에 붙인다(쪽 끝에 제목이 홀로 남지 않게).
- **한 쪽보다 긴 표는 문서에서 쪼갠다** — 주제별 하위 표(h4 제목)로 나누고, 하위 표 첫 행에 앞 표를 가리키는 〃 를 두지 않는다. 블록이 한 쪽을 넘으면 브라우저가 어쩔 수 없이 나누므로 문서 쪽 해결이 원칙이다.
- 생성 뒤 자동 검사 `00_Lawbook/tools/pdf_check.py`(도구가 QVEST_PY 로 호출) — 표마다 머리 행이 PDF 에 정확히 한 번 나와야 한다(갈린 표는 다음 쪽에 머리 행이 반복된다). 갈림이 있으면 도구가 멈춘다. 양성 대조(10-15): 쪼개기 전 용어집 → 갈린 표 3개 검출 · 실패.

## 생성 뒤 확인(매번)

1. 도구의 `[pdf-check]` 줄 — `split` 비어 있음 · `bad_fonts` 비어 있음(대체 글꼴 = 굴림 · 맑은 고딕 등 없음) · `ok: true`.
2. 첫 쪽 · 표가 있는 쪽을 래스터로 떠서 눈으로 본다(글꼴 굵기 · 표 배치).
