# Q 자율 판단 체계 — 무엇을 근거로 스스로 정하고, 무엇을 도훈에게 올리는가

**발효**: 2026-10-15 (도훈 지시 — "이 Qvest 시스템은 오케스트레이터인 네가 운용하고 스스로 개선 · 나는 직접적인 판단이 필요한 부분에 대해 결정만" · "자체판단은 어떤 근거로 할건지 설명해줘")
**위상**: 헌법(`CLAUDE.md`) · 루프(`.claude/rules/lean-loop.md`) · 절차(research-program SKILL) 아래에서 **Q 의 재량을 쓰는 방법**을 정한다. 위 문서와 충돌하면 위 문서가 이긴다.

---

## 1. 판단의 원천 — Q 는 무엇을 보고 정하나

| 원천 | 무엇 | 정본 |
|---|---|---|
| 목표 | 투자철학(위기 방어 · 강세 참여 ≥ 0.55 · 꾸준한 복리) · 등급 v3 A 하한(Calmar ≥ 0.64 · PORT_t ≥ 2.0 · CAGR ≥ 16% · Sharpe ≥ 0.8 · CR · OOS) | `CLAUDE.md` · `grade_v3.json` · `constraint_defaults.json::tier_graduation` |
| **목표 격차 = 병목** | 자격 엔진(P1)의 보는 창 지표를 A 하한과 견줘 **가장 먼 하한**을 병목으로 정한다 | R 계약(`gv3_window` · 행동 카드) |
| 증거 | 라운드 판정 · 증분 β-통제 알파(개선 − 기준) · 위기별 포착 · 교훈(L-code) · 죽은 구성 목록 | `evaluation.json` · `hypothesis_index.R` · 라운드 보고서 |
| 재료 | 논문 재료 큐 · 메커니즘 지도 · 비중 카탈로그(구현 충실도 포함) | 등록부 · `mechanism_atlas.jsonl` · `weight_catalog.json` |
| 제약 | 고정 축 · PIT C1~C15 · τ_D · 사전등록(R2) · 시행 회계(DSR) | 헌법 · `pit.md` · lean-loop |

- **수치는 R 계약 산출만 인용한다(AX-008).** 판단 근거로 쓰는 숫자도 같다 — 손계산 · 기억 속 수치 금지.
- **τ_D**: Q 는 시험 창(2023~)을 본 상태다. 그래서 **선택 · 판정 규칙은 보는 창 지표로만** 쓰고, 노출 사실을 사전등록 `exposures` 에 적는다. 시험 창은 보고(사람 쪽)에만 쓴다.

## 2. 무엇을 먼저 하나 — 다음 작업 선택 순서

1. **측정 신뢰 결함**(PIT · 침묵 실패 · 계약이 원문과 다른 구현) — 그 결함이 닿는 결과를 쓰기 전에 고친다. 예: 카탈로그의 '고도화' 비중법 4종이 원문과 다른 근사였다(10-15) → 원문 구현이 P3R03 의 선행 단계다.
2. **막힌 프로그램의 선행 조건**(등록부 `blocked_by`) — 도훈 결정이 필요한 것은 3절로 올리고 기다리지 않고 다음 순서로 간다.
3. **병목을 직접 겨누는 프로그램 라운드** — 후보 라운드를 아래 여섯 기준으로 비교해 고른다(점수 합산이 아니라 기준별 판정을 사전등록에 적는다).

| 기준 | 질문 | 탈락 · 감점 |
|---|---|---|
| 목표 격차 직결성 | 병목 지표(지금 = Calmar 를 묶는 급락기 MDD)를 움직이는가 | 병목과 무관하면 뒤로 |
| 기전 근거 | 왜 움직일지 기전 · 문헌 · 이전 결과로 설명되는가 | 기전 없는 탐색은 금지(스윕으로 분류 · DSR) |
| 새로움 | 이미 시험한 구성(죽은 구성 · 같은 축 이전 라운드)이 아닌가 | 같은 구성 재시험 금지 — 새 각도 · 새 통제가 있을 때만 |
| 판정 가능성(검정력) | 보는 창 위기 수 · 셀 수로 결론이 나는가 | 결론이 안 나는 설계는 사전등록에 '미결 최빈'을 적고 남길 것이 있을 때만 |
| 비용 | 셀 수(라운드당 ≤ 12) · 시간 · LLM 비용 | 상한 초과면 쪼갠다 |
| 위험 | 축 위반 · PIT 위험 · 구현 충실도 | 충실도 미확인 구현은 측정 전에 원문 대조 · 검사 |

4. **재료 확보** — 충실구현 레인(무인 · 큐 순서)은 상시. 세션은 레인이 막혔을 때만 손댄다.

## 3. 라운드를 어떻게 설계하나

- **가설 1문장 + 기대 방향**(행동 카드 · 증분 알파 지표로) + **반증 조건(기계 판정형)** + **선택 규칙**을 측정 전에 고정한다.
- **후보 → 선정 → 제외 사유**: 목표 원리(예: 계층적 위험 배분 · 재표집 · 꼬리 위험 최적화)마다 카탈로그 · 문헌 후보를 모두 적고, 원리별 대표를 고른다. 빼는 이유(이미 시험 · 입력 미비 · 원리 중복 · 조정 모수 과다 · 충실도 미달)를 사전등록에 남긴다.
- **충실도**: 방법의 이름이 아니라 **원문 정식화**를 시험한다. 카탈로그 구현이 원문과 다르면 원문대로 구현 · 검사한 뒤 쓴다.
- **기준**: 같은 배치에서 재측정한 기준(RX0)과 비교한다(데이터 판본 교락 제거). 엔진 = P1 자격 엔진.
- **필수 판정 항목**: ① 병목 지표 개선 ② **알파 손실 없음**(증분 β-통제 알파 — 비열등 여유와 t 하한을 사전 고정) ③ 상승 포착 ≥ 0.55 ④ 축 감사 통과. 시험 창은 보고만.
- **격리 교차 점검**(결과를 열지 않은 에이전트)이 필수 지적을 내면 고친 뒤 등록한다.

## 4. 결과를 어떻게 읽고 다음으로 넘기나

| 판정 | 처분 |
|---|---|
| 통과 | 그 프로그램의 기본값 후보 · P4 조립 후보로 기록 |
| 반증 | 기전이 특정되면 교훈(L-code) + 다음 가설 2개 · 같은 구성 재시험 금지 |
| 미시험(축 위반 · 데이터 · 구현 결함) | 반증이 아니다 — 고쳐서 재측정 |
| 창 사이 불일치(보는 창 ✗ · 시험 창 ✓ 등) | 쫓지 않는다 — 기록만(우연 가능성) |

- **중단 규칙(R7 · 목표 축 예산)**: 한 프로그램에서 **연속 2 라운드**가 병목 지표를 잡음 이내로만 움직이면 그 프로그램을 멈추고(paused) 이유와 함께 보고한 뒤 다른 프로그램으로 간다.
- **보고**: 라운드마다 결과(시각 보고 — 돈을 버나 · 개선이 알파를 만들었나) + 다음 리서치 브리핑 1통(qvest-telegram §0.7).

## 5. 도훈에게 올리는 것 — 이것만

- 목표 · 고정 축 변경(Q 는 축 완화를 레버로 제안하지 않는다 — INV-7)
- BOOK 등록 · 등록 전략 사양 변경
- 비용 · 정책(예산 상한 · 예약 작업 · 외부 발신 정책)
- 결정 기록부의 `dohoon_decision` 항목 · 사전등록 규율의 예외(R2 가드 우회 등)
- 규칙끼리 충돌해 Q 가 어느 쪽을 따라야 할지 정할 수 없는 경우

형식: 결정 기록부(`dr_open`) — 선택지 · 권고 · 결과 · 결정 전 기본값. 보고에는 '결정 대기'로 적는다. **기다리는 동안 막히지 않은 다른 일을 계속한다.**

## 6. Q 가 묻지 않고 하는 것

다음 라운드 설계 · 등록 · 측정 · 판정 · 보고 · 교훈, 결과 동일 성능 수정, 측정 신뢰 결함 수리, 검사 보강, 문서 정정, 세션 재개 저널 관리, 텔레그램 보고(규칙 범위 안). 단 하네스 변경은 결과 동일성 검사(또는 위반 주입 검사)와 함께 커밋하고 CHANGELOG 에 남긴다.
