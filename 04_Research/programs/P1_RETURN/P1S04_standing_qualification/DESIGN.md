## 5. 첫 판정 절차(판 2 DESIGN §5 승계 · 판 3 차이만)
1. 등록(철학 P1 + 판단 T1 영수증 · 격리 점검 · `tick_hold` 를 판 폴더 커밋에 넣은 뒤).
2. scan 순서(손으로 · tick_hold 아래 · 원장은 추가 전용이라 되돌릴 수 없다 — 격리 점검 v1 S-3): `scan --dry-run`(쓰기 없음 · 사유 코드별 개수만 · 성과 수치 없음 · 등록 뒤 미리보기라 노출 [12] 와 충돌하지 않는다) → `scan --max 0`(시드만 enqueue · standing.R:1243) → 이상 없으면 `scan`.
3. 시드 측정 = GPU 창(도훈 결정 — 레인 양보 · 워커 3 · `PYTHON_CPU_COUNT=4`). 감시 셸 · 판정 전 점검은 **v4 로 옮겨** 판 3 경로에 둔다(격리 점검 v1 R-3): 지문 = v4 `fingerprint.sh`(결합용 뷰 줄 포함 — 판 2 감시 셸의 v3 지문은 뷰가 없다 · p1s02_seed_watch.sh:24) · 판정 전 점검 = v4 `load.R` 적재(prejudge_check.R:20 은 v3) · 측정 시간 가정(판 2 = 6시간 · 워커 8 시절)을 워커 3 · DNN 캐시(입력 내용 주소)로 다시 잡는다. 등록 뒤 · 측정 전에 만든다(`tools/p1s04_seed_watch.sh` · `tools/prejudge_check.R`).
4. 판정 전 점검 → judge → tick_hold 삭제. 판정 전 점검의 기대값(엔진 신호일 수 — 판 2 의 `--expect-engine-dates 268`)은 측정 때 자료의 마지막 월에 달려 있으므로 측정 직전에 다시 센다(격리 점검 v1 R-3 넷째 · v2 선택). 판정 전 점검에서 측정 로그의 torch 판(engine.R 가 찍는다)을 본다 — torch · venv 판은 핀 밖이다(pins.R 의 패키지 핀은 R 다섯뿐 · DNN 캐시 키에도 torch 판 없음 · 격리 점검 v1 S-6). 등록과 시드 측정 사이에 venv 를 바꾸지 않는다.
5. 상설 판에서 쓰는 단계는 scan · standing-measure · measure-item · judge · standing-report · standing-status · superfan-mark 뿐이다 — `round.sh <판 3> measure` · `evaluate`(비상설 단계)는 GPU 관문 없이 시드 DNN 을 돌리고 비상설 판정 파일을 쓰므로 쓰지 않는다(격리 점검 v1 S-5).
6. 핀이 갈리는 창을 짧게 둔다(격리 점검 v1 S-7 — 판 2 는 등록과 측정 사이 등급 계약 교체로 멈췄다): 시드 판정이 끝날 때까지 핀 대상(등급 계약 · 셀 엔진 · 하네스 · 커넥터) 교체는 '측정 · 평가 끝난 뒤 미러 → 원자 교체' 순서로 미룬다(메모리 카드 · 등급 v3.5 교체 선례).

7. **통과 뒤 순서(철학 P1 R-20261115-007 · C-053 · C-054 · C-055 수용)**: ① 시드 · 레인 칸이 통과하면 철학 P2 표식 전까지 열린 사슬 판 전부(지금 P4C01)에 `tick_hold` 를 둔다 — v4 무인 걸음은 풀 eligible 레인 행을 블렌드 상대로 받을 수 있다(p4.R 블렌드 상대 = 풀 자격만). ② 시드 통과 보고를 손으로 보낼 때 결론 범위 줄('시드 미결 · 단독 기저 아님 · 같은 계보 두 구성')을 먼저 싣는다. ③ 철학 P2 한 줄을 담은 보고를 **보낸 뒤에만** `superfan-mark`(표식 = 리뷰 id 만 남고 발송은 남지 않는다). ④ 이 판 통과 칸을 쓰는 사슬 판은 철학 P1 에 저위험 · 저β 표기(레인 행은 β 와 무관하게 '수익 엔진'으로 나온다 → 측정 β 로 적는다) · 시드 띠 조건 · E3 계보 시행(264)을 싣는다.
   - (11-15 첫 판정 뒤 · 철학 P2 R-20261115-013 C-096 · C-097 · 판단 J-20261115-009) 시드 칸(E2 · E3)을 기저 · 블렌드 상대로 받는 사슬은 첫 걸음 전에 ⓐ 재시드 2개 이상(시드 띠 · 시드당 GPU 약 3시간 — 첫 판정 패킷에서 앞선 같은 사양과 대형주 강세 참여가 달라 '같은 추첨의 재현'이 서지 않았다) ⓑ 그 칸의 유동성 3분위 위기 손익 귀속(round_core v4 `p2.R` `rc_p2_liq_tercile_cell` · 보유 · 수익을 τ_D 로 자른다)을 잰다 — P2 패킷 판독: E3 의 2020-01 위기 손실 대부분이 크기 하위 분위에서 났다. 사슬 판단 T1 이 ⓐ ⓑ 를 확인한다. 걸음 가설 후보 = 크기 · 유동성 하위 분위의 위기 손실 집중 → 하한 블록. 판 사양은 바꾸지 않는다(새 판 아님).

## 6. 알려진 한계
- **레인 갈래 기계 관문 없음(철학 C-053 · 다음 코어 판 후보)**: v4 기저 풀은 레인 행에 철학 영수증 · 저위험 확인 · 보류 요청을 읽지 않는다 — 그 빈칸은 §5-7 절차가 닫는다.
- 결론 범위 [15] 의 '빈칸 14~24 … 헌장 결정 전'은 도훈 결정(CHARTER-GAP-BULL-PARTICIPATION-UNIT · (가) 현행 유지) 뒤로 낡았다 — [1](코어 v4 레인 철학 줄)이 정본이다(철학 C-056 · 사양 문장은 판 2 승계라 그대로 둔다).
- **결론 범위 [23] 의 '걸음 전에' 확인자(격리 점검 v2 R-A · 사양은 두고 여기에 뜻을 적는다)**: 판단 T1 은 사슬 판 등록 때만 보고 걸음은 리뷰하지 않는다(무인 틱이 걸음을 열고 블렌드 상대는 기저 풀 자격만 본다). 그래서 이 판(레인 갈래) 통과 칸을 쓰는 사슬은 **등록 때 판단 T1 이 그 칸의 철학 P2 리뷰 id 를 확인한 칸만** 사슬 목적(purpose)의 기저 · 부품 범위로 적는다 — 목적이 부품을 묶는다(P4C01 선례: 부품 = 동일가중 자체 사양 엔진만). 걸음마다 기계 확인은 다음 코어 판 후보.
- **(11-15 정정 · 판단 C-20261115-079)** 위 줄의 '목적이 부품을 묶는다(P4C01 선례)'는 코어 v4 사슬에선 거짓이었다 — 목적 글은 생성기 입력에 없었다(P4C01 첫 무인 틱 실패로 드러남 · 같은 설계를 코어 v5 P4C02 로 재등록). 코어 v5 사슬은 목적 글이 설계 입력 §0 에 실리고, 부품 범위는 `step_policy`(blocks · axes · part_engine_rx)를 건 사슬에서만 기계로 묶인다(`p4.R` `rc_p4_step_open` → `.rcp4_step_policy_why`). 이 판 통과 칸(레인 엔진 `RP_AUTO_*`)은 P4C02 정책 정규식 밖이라 P4C02 부품이 될 수 없다 — §5-7 ① 의 '열린 사슬 판 보류'는 P4C02 에선 기계가 대신하고, 정책 없는 사슬엔 그대로다.
- 판 2 DESIGN §6 그대로(결론 범위 [3]~[20] 18 줄 승계 · 판 3 정정 줄 [24] — '코어 v3' 표기 = v4 와 같은 동작 · [20] 괄호는 v4 에서 갈림 · [13] '입력' = 자료 판에 달림).
- 레인 갈래 통과 칸 · 시드에는 v4 기저 풀 철학 관문이 없다 — 결론 범위 [23](사슬 판 판단 T1 이 그 칸의 P2 리뷰 id 를 확인 · 절차 · 격리 점검 v1 R-1). 통과 엔진의 철학 P2 한 줄을 일 요약에 싣는 자동 통로도 없다 — 판 2 DESIGN §5 의 절차(세션이 싣는다)를 따른다.
- 판 3 등록 뒤 판 2 는 새 항목을 받지 않는다 — 판 2 의 v3 무인 틱 경로는 보류(tick_hold) 그대로 둔다.
