## 1. 왜 새 판인가

- 판 1 의 첫 실측정(1908.01112)은 두 번 다 측정 무효였다. 원인은 엔진이 아니라 **측정 경로 불일치 셋**이다(설계 README §2-1).
  1. 격자 — 셀 엔진의 신호일은 월말 거래일이고 기저 신호는 날짜가 정확히 같은 행에만 붙었다. 60거래일 격자 엔진은 신호일 112개 중 월말과 겹치는 날이 1개였다.
  2. 시작일 — 러너는 엔진에 측정 시작일을 넘기는데 셀 경로는 넘기지 않았다. 엔진마다 다른 기본 시작일로 떨어졌고(2005-01-01 14개 · 자료 첫날 9개 · 멈춤 2개), 캐시 적중 여부에 따라 기저 패널이 달라졌다.
  3. 폭 — 포트폴리오만 내는 엔진은 후보가 엔진이 고른 종목뿐이라 실효 시작 규칙(폭 ≥ 보유 × 배수)이 설 수 없다.
- 셋 다 판정 경로(셀 엔진 · 기저 캐시 · 입구)의 변경이므로 R2 에 따라 새 판을 등록한다. **판정 규칙 · 문턱 · 표준 구성 생성 함수는 판 1 과 같다.**
- 판 1 은 판정 0건으로 보류 고정이다(`tick_hold` 유지 · 원장 · 사전등록 무수정).

## 4. 입구(스캔) — 판 2 에서 더한 사유

| 사유 | 조건 | 왜 |
|---|---|---|
| `portfolio_only_base` | 엔진에 FACTORS 대입이 없다(정적) | 비중을 점수로 읽으면 상위 25종이 거래대금 순 · 시총 순 · 최적화가 크게 실은 순으로 뽑힌다(설계 README §2-2) — 오류 없이 판정까지 가는 형태라 측정 무효보다 나쁘다 |
| `breadth_insufficient` | 레인 점수 패널의 보는 창 신호일 중 종목 수 ≥ 보유 상한 × 배수인 날이 없다 | 재면 무효가 확실한 엔진을 '측정 실패 2회 → 사람 확인'으로 보내지 않는다. **필요조건**이다(레인 패널의 개수는 셀 필터 전 값) — 패널을 못 읽으면 막지 않고 표식만 남긴다 |
| `base_off_month_grid` | 레인 점수 패널의 보는 창에 한 달 2개 이상 신호일 | 주간 · 일간 신호 엔진은 셀 경로에서 월말 표본이 된다. 측정 축은 '주간 신호면 주간 리밸'이고 셀 엔진의 주간 신호는 아직 없다 — 축 밖 근사로 자격 판정을 내지 않는다(판단 T4 C-20261111-061) |

숫자는 새로 쓰지 않는다 — 보유 상한 = `constraint_defaults.json::tier_soft_deployment.max_names` · 배수 = 활성 측정 축의 `effective_start.breadth_mult`.

## 5. 첫 판정 절차(판 2 의 첫 항목 — 판정 경로가 실자료에서 처음 끝까지 지난다)

순서(초안 v2 · 격리 교차 점검 v1 F-1 · S-1 · S-2 · R-5 · 판단 T1 C-085 · C-086 · 철학 P1 C1 (다) 반영):

1. **등록 전 리허설**(`rehearsal/` · REHEARSAL.md) — 판정 경로(실제 셀 워커 → 러너 → 측정 관문 → 칸 평가 · β-통제 알파 → judge → 판정 원장 → 보고 드라이런)를 싼 CPU 월말 엔진(12-1 모멘텀)으로 격리 폴더에서 한 번 끝까지 지난다. 결과 요약(`rehearsal/rehearsal_summary.json` · 성과 값 없음)을 초안 v2 의 `rehearsal` 에 싣는다(`rc_draft(rehearse =)` — 등록 조건 ⑤가 기계로 본다). 리허설이 코어 · 운영 파일 결함을 드러내면 등록하지 않고 새 코어 판 여부를 먼저 정한다.
2. **`tick_hold`(첫 줄 = 사유)를 판 폴더와 함께 커밋한 뒤 `register`**(F-1) — 등록본(prereg.json)이 생기는 순간부터 무인 틱(`Qvest_StandingBoard` 매시 :37 · `standing_board_run.sh --send`)이 판을 고를 수 있다. 그 틱은 scan → 측정 → 판정 → 실발송을 한 번에 하고 판정 전 점검 · 측정 창을 거치지 않는다. `tick_hold` 가 있으면 HELD 로 건너뛴다. 등록 직전 확인: `tick_hold` 가 판 폴더 커밋에 들어 있는가 · `git status --porcelain -- <판 폴더>` 가 초안 · drafts · results · rehearsal/out 말고 비었는가.
3. **`scan`(손으로 · `tick_hold` 아래)** — 시드 2건을 원장에 넣는다(S-1 · 원장에 시드가 없으면 `measure-item` 이 "그런 항목이 없다"로 멈춘다 · 감시 셸은 scan 을 하지 않는다). 입구 통과 레인 엔진이 있으면 함께 들어간다(등록 전 미리보기 = 0).
4. **감시 셸**(`tools/p1s02_seed_watch.sh` · 백그라운드 · 세션 밖 분리 실행) — 순서 = 창 확인 → 레인 측정 0 → 측정. 임대를 미리 쥐지 않는다(코어 관문 `rc_gpu_guard` 가 측정 때 잡고 놓는다). 낮 창 시작 08:20~11:45(측정 6시간 가정 · 17:45 전 종료) · 밤/아침 체인 미실행 · 배리어 free · 지문 20분 안정 · 가용 메모리 ≥ 16 GB. 판정 · 발송은 하지 않는다.
   - E3 = E2 직후 follow 대기(격리 점검 v2 R-1 · 11-12): E2 가 ok · 지문 동일일 때만 E3 용 임대를 한 번 선점하고, 시각 창 · 지문 안정 대기 없이 체인 · 배리어 · 메모리 · 레인 조건만 본 뒤 **지문이 E2 측정 시작 때와 같으면** 곧바로 잰다(같은 창 · 같은 자료 판 · 기저 캐시 공유). 지문이 달라졌으면 선점을 놓고 보통 대기로 돌아간다(E3 는 다른 자료 판 — 판정 전 점검에서 본다). E2 가 실패하면 선점하지 않는다.
   - `--expect-engine-dates 268` 은 측정 때 자료의 마지막 월에 달려 있다(점검 v2 선택) — 새 월말이 자료에 들어온 뒤 재면 그만큼 늘어난 값이 정상이다(★면 날짜부터 본다).
5. **`measure-item`** — 감시 셸이 E2 → (E2 ok · 지문 동일이면) E3 를 항목 하나씩 잰다(측정과 판정을 붙이지 않는다).
6. **판정 전 점검 10항목**(`tools/prejudge_check.R <code> --eval` · 설계 README §8 · 판단 T4 C-063 · T1 C-081): 측정 ok · 지문 · 키 파일 · 축 감사 · 실효 시작 날짜 · 칸 평가 · β-통제 알파 유한 · 기저 = 점수 패널(`base_kind`) · 엔진 신호일 집합(레인 패널과 대조 · 없으면 기대값과 대조) · 후보 폭. 시험 창 값은 읽지 않는다(유한한지만 본다). 결함이면 판정하지 않고 멈춰 보고한다.
   - **시드 기대값**(스케줄 절 대조 7/0 · 구축 기록 S2): 첫 엔진 신호일 **2004-07-30** · 엔진 신호일 **268** · 측정 시작일 주입(`start_injected = TRUE`) · 실효 시작이 옛 기본값(2005-01)에 머물지 않음. 명령: `Rscript <판>/tools/prejudge_check.R P1S02_E2_C0 --eval --expect-first-engine-date 2004-07-30 --expect-engine-dates 268`(E3 도 같은 기저라 같은 기대값). `--expect-effective-start` 는 실효 시작 날짜를 미리 알 때만 준다(지금은 모른다 — 날짜를 눈으로 본다).
   - `--eval` 은 읽기 전용이 아니다(S-2): 칸 평가 캐시 `results/<code>/eval.json` · `eval.key` 를 쓴다. 뒤의 `judge` 가 같은 파일을 읽는다(같은 함수 · 판정을 바꾸지 않는다).
7. **`judge`**(손으로) → 판정 원장 · `results/standing/<code>.verdict.json` · `standing_visible.json`.
8. **보고** — `standing-report --send`(통과 = 엔진마다 push · 미달 = 일 요약) → 통과면 판단 T2 + 철학 P2 즉시.
9. **철학 P2 판독 목록**(철학 P1 C1 (다) · 진단 패킷 `results/<code>/visible/` — 패킷에 없는 항목은 '미측정'으로 적는다 · '판독함'으로 접지 않는다): 집중(최소 종목 수 · 유효 종목 수 · 깊은 위기 한 종목 기여) · 숨은 현금(노출 평균 · 리밸 달력 대비 보유 0 달) · 강세 구간별 상승 포착(강세 수 · uc_floor 이상 비율) · 하락/상승 β · MC8 귀속 · 팩터 방향(registry · defensive) · 학습 난수 · CDaR · 회복.
   - 통과 엔진마다 P2 의 한 줄(방향 · 실패 형태 · 귀속)을 그 엔진의 **다음 일 요약에 반드시 싣는다**(철학 C3 — 통과 push 의 판정 줄에는 귀속 없는 위기 하락노출이 실린다 · v3 고정 동안의 대체) · 확인 = `superfan-mark --codes <code> --kind pass --p2 <리뷰 id>` 표식.
   - **실행자 · 통로 · 확인**(격리 점검 v2 R-3): v3 의 `standing-report` 일 요약은 미달 · 미시험 항목만 싣고 통과 엔진의 P2 를 읽지 않는다(standing.R:996-1033). 그래서 'P2 한 줄'은 **Q 가 P2 를 받은 뒤 그 엔진의 다음 [1계층] 보고 1통(`prep_send`)에 싣는다** — 무인 틱의 일 요약은 싣지 않는다(v3). 확인 = 위 `superfan-mark` 표식 + 그 보고의 발송 기록(같은 엔진 이름). 일 요약에 기계로 싣는 것은 다음 코어 판 후보(아래 §6).

## 6. 알려진 한계 · 미집행(결론 범위에 싣는다)
