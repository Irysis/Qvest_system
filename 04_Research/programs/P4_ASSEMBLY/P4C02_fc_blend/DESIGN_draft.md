# P4C02 설계 초안 — 블렌딩 사슬 1호 판 2(코어 v5)

> 사고 기록이다. P4C01 설계 초안(`../P4C01_fc_blend/DESIGN_draft.md`)을 승계한다 — 질문 · 가설 · 반증 · 기저 규칙 · 채택 규칙 7 · 예산 · 닫기 판독 ①~⑤ · 감독 반영(철학 P1 · 판단 T1)은 그대로이고, 여기에는 **판 2 에서 달라진 것**만 적는다.
> 사양 생성 = `tools/init_p4c02.R`(P4C01 사슬 판에서 채택 규칙 · 예산 · 목적 글을 읽어 판 2 줄만 고친다 · 기저는 같은 기계 규칙으로 다시 고르고 P4C01 기저와 다르면 멈춘다).

## 1. 왜 판 2

- P4C01 은 등록(3d6485247) · 기저 칸 손 측정(7169d56c6 · 같은 구성 · 보는 창 지표 18 = 등록 값 · 차이 0) 뒤 **첫 무인 틱(11-15 08:37)이 생성기 작업 폴더 만들기에서 멈췄다**. 설계 입력 §1 의 사유 코드 설명(코어 상수 `RC_P4_REASONS`)에 든 리뷰 id 날짜 두 개와 '전 기간' · 'T4' 가 처방 입력 검사(`rc_input_issues` — 마지막 전수 검사)에 걸린다. 무인 틱은 늘 기저 풀을 넘기므로 **풀을 넘기는 모든 v4 사슬이 같다** — 코어 v4 결함이다(출시 시험 71/0 · 격리 점검이 못 잡았다).
- 고치다 본 둘째 구멍: **목적 글(purpose)은 생성기 입력에 없었다**(작업 폴더 네 파일 — 설계 입력 · 헌장 · 도구 상자 · 부모 칸 사양 — 어디에도). P4C01 의 범위 문장('걸음 = blend 만' · '부품 = 동일가중 T0 만 — 기계 차단 없음 · 생성기가 지킨다')을 생성기가 볼 수 없었다 — 판단 C-20261115-048 · 철학 C-20261115-038 의 '생성기가 지킨다' 전제가 거짓이었다.
- 출시 판은 고치지 않는다(RELEASES immutability) → **코어 v5**(v4 + 생성기 입력 수리 셋 — 아래 §2)로 같은 설계를 새 사슬 판에 다시 등록한다.

## 3. P4C01 처리

- P4C01 = 걸음 0 · **닫지 않는다**(닫기 = 최종 후보 재채점 · 결과 원장 — 걸음 없는 기저의 재채점은 뜻이 없고 결과 원장에 탐침 · 교훈을 남길 라운드도 아니다). `tick_hold` 고정(사유 문장) — 판 2(P1S02 — 측정 0 · 보류 고정) 선례.
- P4C01 기저 측정 1 은 P4C02 닫기 시행 집합에 든다(같은 기저 · 코어 규칙).

## 4. 절차

1. 코어 v5 변경분 점검(격리) → `RELEASES.json` v5 → `init_p4c02.R`(쓰기) → 철학 P1 + 판단 T1(동시 · 판 2 변경분 위주) → `round.sh <사슬> p4-check` → `p4-register --p1 <id> --t1 <id>`.
2. `p4-base-measure`(손 · 아침 체인 05:55~08:00 밖) → 기저가 P4C01 기저 측정과 같은 구성 · 같은 보는 창 지표인지 확인 → **닫기 판독 ⑥ 기준 칸 사이드카**(유동성 3분위 위기 손익 귀속 · P2 계약 `rc_p2_liq_tercile_cell` 재사용 · 보는 창 · 기록만 — 걸음과 병행해도 된다 · 닫기 전 필수 · 못 재면 '소형주 착시 미측정'). P4C01 k0 와 같은 칸이라 어느 쪽 k0 에서 한 번 내면 된다(철학 C-20261115-082).
   - **걸음 열기 진입점 양성 대조**(변경분 점검 R-2 (a) · 재점검 R-5): tick_hold 를 둔 채로 · 대조 칸 사양은 사슬 디렉터리 밖(스크래치)에 두고 · blend 밖 블록(weighting) · 바꿀 축 밖(factors) · 정책 밖 부품(IC 가중) · 기저 뺀 블렌드 · 한 걸음 둘 — 다섯이 모두 정책 사유로 거부되는지 본다(거부되는 열기는 원장에 아무것도 쓰지 않는다) → 기록 뒤 다음 단계.
3. **생성기 작업 폴더 시험**(`round.sh <사슬> p4-workdir --out <스크래치 빈 폴더>` — 무인 틱과 같은 호출 · 사슬 폴더 밖) → 네 파일이 만들어지고 §0 에 목적 · 정책 줄이 있는지 본다.
4. `tick_hold` 삭제 → 무인 틱(Qvest_StandingBoard 매시 37분 → chain_tick.sh)이 걸음을 잇는다. 첫 걸음 열림 · 측정을 확인한다.
5. P1S04 DESIGN §5-7 ①(레인 갈래 통과 뒤 열린 사슬 보류)은 P4C02 에선 걸음 정책이 레인 엔진 부품을 막아 보류 없이도 같은 효과다(다른 열린 사슬엔 그대로).

## 5. 알려진 한계

- **목적 글은 이제 처방 입력이다**(설계 입력 §0 · 변경분 점검 R-4): 기계 검사는 날짜 · 연도 · 등급 표기 · '키워드 + 수치'만 막는다 — 수치 없는 정성 서술(예: 어떤 엔진이 강건성 구간에서 약했다)은 지난다. 목적 글은 교훈 카드와 같은 τ_D 규율로 쓴다(P4C02 목적 = P4C01 목적(기저 측정 전 작성) + 한 줄 · 시험 구간 서술 없음).
- 걸음 정책 = 블록 유형 · 바뀐 칸 사양 축 · 엔진 경로 · 블렌드 단위(부모 + 1)를 본다. 블렌드 비중(engine_blend = 월별 순위 Z 등가중 고정)과 성과는 채택 규칙이 본다(P4C01 과 같다).
- 저β 표기는 풀 표 열과 목적 글뿐 — 가설 · 기전 글이 저β 상대를 '방어'로 부르는지는 걸음 단위 기계가 없다(닫기 P2 가 읽는다 · 철학 C-20261115-085 꼬리표안은 다음 판 후보).
- 생성기 g1(`_generator/g1/step.md`)은 블록 9종을 다 열거하고 §0 을 모른다(판단 C-20261115-078 (iii)) — 정책 밖 제안은 걸음 열기에서 기계로 거부되고(`gen_fail` → 연속 상한 → 차단 + 경보) 조용히 들어오지 않는다. 거부가 실제로 생기면 생성기 새 판(§0 범위 한 줄 · rxg_revise + 철학 검토)을 연다.
- 생성기 판(`06_Registry/rx_generator.json`)은 등록 때 판을 핀한다 — P4C01 등록 뒤 판이 바뀌었으면 판 2 는 지금 판이다(사슬 판 generator 항목에 적힌다).
- 목적 글의 § 가림은 리뷰 · 결정 id 안의 8자리 날짜만 가린다(변경분 점검 M-1 — 그 밖의 날짜 · 연도는 남겨 처방 입력 검사가 등록을 거부한다) — id 의 나머지(C-§-048)는 남는다.
