# 성능 규칙 — round_core · 라운드 고유 규칙(round_ext.R) · 엔진 코드

1계층 속도 계획 5-2 · 도훈 10-20 "코드 작성 시 최적화를 통한 실행속도 극대화" 지시에 따른 규칙이다. 격리 교차 점검의 점검 항목이기도 하다.

## 원칙
- **재고 나서 고친다.** 근거는 실행 시간 기록(`.cache/round_core/perf/<round>.jsonl`)과 Rprof(`QVEST_PROFILE=1`)다.
  - 10-15 의 교훈: 평가 시간의 95% 가 날짜를 문자열로 바꾸는 한 줄에서 나왔다. 짐작으로는 찾지 못했다.
- **결과가 바뀌는 최적화는 쓰지 않는다.** 채택 조건은 바이트 동일, 또는 run_id 류 열을 뺀 바이트 동일이다. 혼합 정밀도 · 비결정 커널 · 난수 호출 순서 변경은 금지다.
- **최적화마다 전후 시간을 기록**한다(`PERF.json`).

## R
- **키와 날짜**
  - 날짜는 정수 일 번호(`as.integer(Date)`), 종목은 정수 코드로 다룬다.
  - 반복문 안에서 Date ↔ 문자 변환(`format` · `%in%` 의 mtfrm)을 하지 않는다.
  - 큰 표의 `%in%` 반복 대신 data.table 키 조인 · `match` 를 한 번 쓴다.
- **한 번 쪼개 여러 번 쓴다**
  - 리밸런싱 창별 수익 행렬을 한 번 만들어 목록으로 색인한다.
  - 리밸런싱마다 전체 표를 부분집합하지 않는다.
- **행렬 연산** — `crossprod` · `matrixStats` 누적 · 열 연산을 쓴다.
  - `apply` 반복과, 반복문 안에서 객체를 키우는 일을 피한다.
  - 미리 할당한다.
- **한 번 읽는다**
  - parquet 는 필요한 열만 읽는다(arrow `col_select`).
  - 원자료는 프로세스당 한 번 읽는다(코어 `rc_eval_env` 의 `raw` 메모).
  - 디스크 캐시는 `.cache/round_core/` 에 빠른 이진 형식(qs/fst · 비압축 RDS)으로 둔다.
  - 캐시 키에는 입력 지문을 넣는다. 재측정 뒤 옛 결과를 쓰지 않게 하려는 것이다.
- **병렬** — 워커 수는 코어와 여유 RAM 으로 정한다.
  - K>1 이면 워커마다 `setDTthreads(1)` · BLAS 1스레드로 둔다.
  - 측정이 끝난 칸부터 평가한다.
- **Rcpp** — 측정으로 확인된 뜨거운 반복문에만, 비트 동일 검사와 함께 쓴다.

## Python · DNN 엔진
- 결과가 같은 최적화만 쓴다: 특징 · 예측 캐시 · 데이터 적재 · 배치 · 핀 메모리.
- 모델 캐시 키 = 엔진 md5 · 월별 as-of 입력 지문. 이렇게 하면 증분 재학습만 하게 된다.
- `cudnn.benchmark = False` · 결정 알고리즘을 쓰고, 시드는 기존 순서를 보존한다.
