## §1 신규 상장 동기화 체계(구축 ✔ · OHLCVS 적용 ✔)

```
[KRX Open API 종목기본정보]  data/krx_listing_snapshot.R  → .cache/krx/{stk,ksq}_info/*_<d>.parquet
        ↓
[정본 종목 목록]  data/qw_datakey_master.py --update     → 06_Registry/qw_datakey_master.json (추가만 · 순서 고정)
        ↓
[DB 반영]  ops/qw_datakey_sync.ps1                       → 각 DB DATA_Key 끝에 붙이기 + 행 8 정렬 검증 + 백업 + 저장
        ↓                                                  → .cache/qw_backfill_pending.json (DB별 보충 시작일)
[보충 수급]  ops/qw_refresh.ps1 -FromOverride <DB>=<시작일> → 적재기(incremental_update_file.R) → RAWDATA · us_* · investor · consensus
```

- **정본 규칙**(기존 목록 구성을 실측해 그대로 따름): KRX `SECUGRP_NM ∈ {주권, 외국주권, 주식예탁증권}` ∧ `KIND_STKCERT_TP_NM = 보통주` ∧ 이름에 '스팩' · '기업인수목적' 없음. 실측: 기존 목록 ∩ 상장 = 주권 보통주 2,495 · 외국주권 12 · 주식예탁증권 9 · 스팩 0. 폐지 종목은 지우지 않는다(생존 편향 · C6).
- **정본 초기값** = OHLCVS DATA_Key 순서 3,717 + 3개 DB 전용 4(A067250 · A194610 · A300090 · A402360) = 3,721 → 11-06 KRX 대조로 46종 추가 = **3,767** ✔. 상장일 보충 2,516.
- **끝 붙이기만**(PLAN §5.2 ⑦ 절차): 가운데 삽입 · 정렬 · 삭제 · A/B 수식 수정 금지 — 질의 시트 행 8 = `{=TRANSPOSE(DATA_Key!A2:A10002)}`(B8:NTP8 = DATA_Key 2~10000행). 저장 전 검증: 새 행 A 값 = 붙인 코드 · 다음 행 빈칸 · 모든 질의 시트 행 8 의 기존 열 불변 · 새 열 = 붙인 코드 · 다음 열 빈칸 · FilterMode False. 하나라도 어긋나면 저장 없이 닫는다.
- **OHLCVS 적용(11-08 15:0x)** ✔: 3,717 → 3,767(50 붙임) · 검증 통과 · 원본 백업 `03_Universe/_backup_datakey_20261108/OHLCVS_update.xlsx`. 사본 독립 대조(openpyxl): 행 8 기존 3,717열 · 데이터 15~20행 동일, 새 열 = 붙인 코드 ✔.
- **PS 5.1 함정 2건(수리 반영)**: ① 2차원 COM 배열을 함수에서 그대로 반환하면 파이프라인 펼침에서 "Insufficient memory" → `return ,(...)` ② PowerShell `object[,]` 를 `Range.Value2` 에 통째로 대입해도 같은 오류 → 셀 단위 쓰기.
- **잔여**: 03-28 이전 상장 5종(케이뱅크 03-05 · 에스팀 03-06 · 아이엠바이오로직스 03-20 · 한패스 03-25 · 메쥬 03-26)의 상장일~03-27 구간 — OHLCVS 적재기가 기준 통합문서 끝(03-27) 이전 날짜를 버린다(`incremental_update_file.R` `Date > base_max`). 새 종목만 더하는 보충 경로가 필요하다(기존 종목 행은 건드리지 않는 조건).
