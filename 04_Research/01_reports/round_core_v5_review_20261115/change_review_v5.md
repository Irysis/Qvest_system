  - 남는 위험: 날짜를 일부러 id 처럼 적으면 빠져나간다. 이것은 등록 리뷰(P1 · T1)가 맡는다.

## 선택

- **S-1 등록과 걸음 열기가 기저를 다르게 읽는다.** 등록의 정책 검사는 `spec$base$engine_path`(풀 값)로 기저를 본다. 걸음 열기는 기저 칸 사양의 `base_signal`(물려받은 부품)을 본다. 지금 생성기들로는 둘이 같지만, 등록에서도 `.rcp4_step_policy_why`를 기저 칸 사양에 돌리면 "등록 통과 ⇒ 물려받은 부품도 통과"가 보장된다.
- **S-2 정책 거부가 `invalid`로 세진다.** `chain_tick.sh:232-237`에는 정책 거부를 가리키는 갈래가 없다. 그래서 정책 거부는 `gen_fail invalid`로 세지고, 상한에 닿으면 사유 없는 차단이 된다. `*"걸음 정책"*) gen_fail "$cid" policy ;;`를 더하면 진단이 쉬워진다. 선택으로 `ct_compile`에서 미리 검사하면, 칸 사양을 썼다가 지우는 일이 없어진다. 둘 다 코어 밖이다.
- **S-3 표기 정리.**
  - 바뀐 다섯 파일(p4 · util · driver · measure_cell · standing)의 머리 주석이 아직 "round_core v4"다. 바뀌지 않은 14파일은 v4 와 같은 바이트로 두는 편이 대조에 좋다.
  - `.rcp4_step_policy_check`는 기저가 NA 일 때 "NA"를 찍는다. `%||%`가 NA 를 비어 있다고 보지 않기 때문이다.
  - 사유 코드 설명을 만들 때마다 생략 메시지 2줄이 틱 로그에 쌓인다.
- **S-4 다른 판의 사슬을 손대도 막히지 않는다.**
  - v4 코어는 v5 사슬의 `step_policy`를 모르는 필드로 보고 조용히 무시한다. 지금 이것을 막는 것은 라우팅뿐이다.
  - 다음 판부터는 `.rcp4_state`를 쓰기 경로(열기 · 측정 · 판정 · 닫기)에서 부를 때, 사슬의 `core_version`이 `RC_VERSION`과 다르면 거부하는 관문을 두기를 권한다.
  - P4C01 은 v5 로도 풀리지 않는다(v4 사슬). tick_hold 를 유지하거나 감독 아래 닫는다.
- **S-5 생략된 두 사유 코드의 설명을 되살린다.** v5 는 새 판이라 상수를 고칠 수 있다. 생성기가 보는 설명과 id 출처를 나누면(예: `RC_P4_REASONS_SOURCE`), `philosophy_unread`와 `lowrisk_confirm_pending`도 설명이 실린다. 지금은 코드만 보인다.
- **S-6 `.rcp4_norm_spec`의 `$` 부분 일치(v1 부터 있던 것).** p4.R:1150 의 `b$path`는 `paths`와 부분 일치한다. 그래서 정규화된 블렌드 사양에 `path`(첫 부품) 칸이 하나 더 생긴다(탐침: 이름 = kind,paths,path). 정책 검사는 `unique()` 덕분에 영향이 없다. 다음 판에서 `[["path", exact = TRUE]]`로 바꾸면 된다.

### 해소된 것

- **M-1**: 가림이 이제 id 꼴 날짜만 친다. 일곱 꼴과 ISO 꼴은 NULL 이 된다(U3-*). 아래 M-2 의 남은 꼴만 빼면 해소다.

- **S-1**: 등록 때 기저 칸 사양의 부품도 같은 판독(`.rcp4_policy_parts_why`)으로 검사한다(C6).

- **판단 C-074(축 범위)**:
  - `RC_P4_POLICY_AXES` = base_signal + `RC_P4_KEY_BLOCKS` 이름이다. `fixed_axes`는 어휘 밖이다.
  - 걸음 열기에서 `changed = dif$changed`가 넘어간다(p4.R:1290). `dif`가 NULL 이면 축 검사를 건너뛰는데, 그 경우는 부모 번호가 틀렸거나 칸 사양 파일이 없을 때뿐이고, 그때는 다른 사유가 이미 열기를 거부한다. 그래서 받아들여지는 걸음에는 반드시 축 검사가 걸린다.

### M-2 id 날짜 가림 정규식이 8자리 날짜 범위와 소문자 앞말을 id 로 본다

- **위치**: `v5/p4.R:1660`.
- **원인**: 뒤보기 `(?<=[A-Z0-9]-)`가 숫자 뒤의 하이픈도 받는다. 그래서 다음 글들이 가려진 뒤 그대로 보인다(탐침).
  - "측정 창 20200101-20231231 에서 S <수치>"는 "20200101-§ …"로 보인다.
  - "20221231-20240630 구간 낙폭 <수치>"도 같다.
  - "v2-20230101 이후 S <수치>"도 같다.
  - 앞 날짜가 τ_D 이전이면 생성기는 그 수치가 τ_D 를 넘는 구간의 값임을 알 수 있다.
- **고침**: 앞말이 대문자로 시작하는 id 토큰일 때만 날짜 자리를 가린다.
  ```r
  x <- gsub("\\b([A-Z][A-Z0-9]*(?:-[A-Z0-9]+)*-)(?:19|20)[0-9]{6}(?=-[A-Z0-9]|(?![0-9A-Za-z_]))", "\\1§", x, perl = TRUE)
  ```
  - 탐침 결과, 위 세 꼴은 NULL 이 된다.
  - 실제 id 꼴(`C-…-048`, `LOWBETA-…-USE-…`, `FACTOR-SPINE-STAGE1-…`, `OP-…-V102-LADDER`, `GRADE-V33-…`)은 가려진다.
  - P4C01 목적 원문과 `init_p4c02.R` 방식으로 만든 P4C02 목적 글은 그대로 통과한다.
  - `Q-20230315`처럼 일부러 id 꼴로 적은 날짜는 두 식 모두 못 막는다. 이것은 등록 리뷰가 맡는다(주석에 적힌 대로).
- **시험**:
  - U3 에 `range8` · `lower_v` 꼴을 NULL 로 더한다.
  - U2 에 `STAGE1-` 꼴 id 를 더해, 보인다는 것을 단언한다.

### 권고 · 선택(추가)

- **R-5 진입점 대조 조건**: 실제 P4C02 에서 진입점 대조를 할 때 지킬 것.
  - tick_hold 를 둔 채로 한다.
  - 대조용 칸 사양은 사슬 디렉터리 밖(tempdir)에 둔다.
  - 블록 · 축 · 부품 세 갈래를 각각 한 건씩 거부시킨다. 각 건은 정책 사유 외에는 거부될 이유가 없는 칸으로 만든다.
  - 결과를 판단 원장이나 사슬 기록에 남긴 뒤에 tick_hold 를 지운다.
- **S-7 서로 맞지 않는 정책을 등록이 받아들인다.** 탐침에서 `blocks = weighting` + `axes = base_signal`인 정책이 등록 검사를 통과했다. 이런 정책에서는 어떤 걸음도 열리지 않으므로, 생성 실패만 쌓이다가 차단된다. 허용 블록마다 그 블록에 대응하는 허용 축이 하나 이상 있는지 확인하는 일관성 검사를 권한다. 대응 관계는 `RC_P4_KEY_BLOCKS`와 base_signal → base · blend 다.
