## 3. 규칙 블록(R · 설계 §3.4 · §4)

신호일 d 의 U_d = 그날 예측 행 중 q10 · q50 · q90 가 모두 유한한 행. s = q50 − q10(≥ 0 · 재배열 뒤).

| 규칙 | Score |
|---|---|
| Q50 | q50 |
| V1 | q10 순위(동률 평균)/N ≤ 0.2 → NA(후보 제외) · 나머지 q50 |
| V2 | q10 |
| N1 · N2 | q̃10 = q50 − s_perm 으로 V1 · q50 − s_perm |
| S1 · S2 | q̃10 = q50 − s_sigma 로 V1 · q50 − s_sigma |

- **s_perm**: 주 시드 20261018 → runif 흐름에서 달 순번(엔진 `.START` 대비) 하위 시드 → 그날 종목코드 순(C 로케일)의 s 를 `sample.int` 순열. 접두 안정 · 끝나면 전역 난수 상태(.Random.seed · RNGkind) 복원(rf_cell_engine.R null_perm 규약).
- **s_sigma**: σ = 직전 252거래일(격자 연속 거래일) 일 로그수익 sd · 창 끝 t−1 · 유효 관측 ≥ 126 · 수정 종가 · 모멘트 항등식 없이 sd(). σ 유효 종목의 s 다중집합을 σ 오름차순 ↔ s 오름차순으로 재배정(동률 σ = 종목코드 순) · σ 결측 = 그날 s 전체(U_d) 중앙값.
- **s_hist**(철학 P1 C-20261018-065 · D^H 짝 · 점수 규칙은 쓰지 않음 · 기록): h = 그 종목의 학습 표적 y(그날 적격 집합 안 5일 순위 재척도 수익 — 파이썬이 학습하는 열) 중 di ∈ [p − 252, p − 1] ∧ **lab_i ≤ u**(그 신호일 학습 격자 · PIT 단언과 같은 경계) 인 값의 중앙값 − 10% 분위(type 7) · 유효 관측 ≥ 126. s_sigma 와 같은 재배정 함수(`.dt_match_s`) · h 결측 = 그날 s 중앙값.
- **예측표** `_work/qpred/<md5(CODE_VERSION) 8자>_<데이터 지문 8자>.parquet` — 열 13개: Date · Ticker · q10 · q50 · q90 · q10_raw · q50_raw · q90_raw · s_perm · s_sigma · sigma252 · s_hist · h_hist(실현 라벨 없음). 데이터 지문 = md5(시작일 · 신호일 목록 · 달별 내용 주소 캐시 키(k 순) · σ 표 · h 표 · 짝 상수(순열 시드 · σ/h 창 · 하한 · τ)). 규칙과 무관 → 7 엔진이 같은 이름 · 같은 내용. 이미 있으면 내용을 대조하고(같으면 쓰기 생략 · 다르면 비결정으로 중단), 없으면 임시 파일 → 교체. 읽기는 `mmap = FALSE`(Windows 에서 매핑이 남으면 다른 실행의 교체가 오류 1224 로 실패 — 시험에서 실측) · 교체 실패 시 같은 내용이 이미 있으면 통과. 로그 `[DT qpred] path=<경로> rows=<n> months=<m>`.

## 5. 양성 대조(이분산 합성 · 설계 §3.3) — 리허설로 정한 합성 상수

합성: X ~ U(0,1)^31 · f = PC_F_SD·(f0 − 평균)/sd(f0), f0 = Xw + 0.5 sin(6X₁)(rev3 중심 형태 · 평균/sd 는 학습 표본) · g = 0.25 + 2X₂ · y = f + g·ε. 학습 y 와 홀드아웃 라벨 = 학습 표본 경험 CDF F̂ 로 (0, 1] · 참값 m = F̂(f) · l = F̂(f + g z₀.₁) · u = F̂(f + g z₀.₉). 같은 `fit_predict`(20 epoch · 배치 500 · Adam 1e-3) · 시드 = 첫 달 시드 + 7(= 20020705).

## 7. 공통 난수 사실(C-20261018-054 (0) · CPU 실측 · 수정 없음)

`fit_predict` 순서(두 모델 같음): `torch.manual_seed(seed)` → 별도 CPU 생성기 `gen.manual_seed(seed)`(미니배치 순서) → `DNN(m)` 을 **CPU 에서 생성** → `.to(DEVICE)` → 매 스텝 `randperm(generator=gen)` · dropout 은 텐서 장치의 기본 생성기.

| 사실(같은 시드 20020698) | 결과 |
|---|---|
| 은닉층 5개 초기 가중치 · 편향 | **같다**(출력층이 마지막에 생성되므로 그 전 난수 소비가 같다) |
| 출력층 초기화 | 다르다(1×50 대 3×50 · 첫 행부터 다름) |
| 초기화 뒤 CPU 기본 생성기 상태 | 다르다 — 분위 모델이 float32 uniform 468개 상당을 더 쓴다(연산별 소비는 원소 수에 비례하지 않는다: Linear 생성 51 대 153 · trunc_normal_ 132 대 332 — 이 torch 2.12.1 판의 구현 세부) |
| 미니배치 순서 | **같다**(별도 생성기 `gen`) |
| CPU dropout 마스크(첫 스텝 은닉 출력) | **다르다** · 난수 상태만 맞추면 같다 → 차이의 원천 = 출력층 초기화의 추가 소비뿐 |
| CUDA(실측 아님 · 코드 구조상 추론) | 초기화는 CPU 생성기만 쓰고 dropout 은 CUDA 생성기(`torch.manual_seed` 가 함께 시드 · 초기화가 건드리지 않음)를 쓰며, 두 모델의 dropout 호출(은닉 5층 · 같은 배치 모양 · 같은 스텝 수)이 같으므로 **CUDA 에서는 RX0 와 분위 모델이 같은 dropout 난수 흐름 · 같은 은닉층 초기값 · 같은 배치 순서를 공유하고 출력층 초기화만 다를 것** — 설계 §3.1 의 "dropout 난수 흐름은 RX0 와 같지 않다" 는 CPU 에서만 참이다. GPU 미사용 지시로 검증하지 않았다 |

함의(판독용 · 판정 아님): CUDA 에서 RX0 ↔ 분위 처치의 차이는 독립 시드 잡음이 아니라 '공통 난수 + 출력층 초기화 · 손실' 차이에 가깝다. RX0S(시드 자체를 바꿈)는 은닉 초기값 · dropout · 배치 순서를 모두 바꾸므로 시드 잡음 띠를 잰다.

## 9. 설계와 다르게 하거나 해석한 곳 · 열린 문제

1. **양성 대조 판정 = 날 머리 ∧ 재배열 머리**(§5). 설계 표기 q̂ 를 재배열 값으로만 읽으면 부호 반전 · 머리 뒤바꿈 뮤턴트가 통과한다(실측). 새 숫자는 없다(같은 문턱).
2. **PC_N = 100,000**(rev3 20,000 아님) — 같은 학습 루틴에서 20,000 은 q90 머리가 덜 배워 정답이 3/3 실패. 설계 §3.3 이 리허설로 정하라고 한 '표본 수'.
3. **f 정규화**: f = 0.5·(f0 − 평균)/sd(f0)(학습 표본) — 중심/폭 상대 크기 상수를 시드와 무관하게 고정하려는 것.
4. **CUDA 미실측**: 양성 대조 여유(ρ ≥ 0.975 대 0.8 · 적중 여유 ≥ 0.03)는 CPU 9 시드 기준. CUDA 는 dropout 난수가 달라 다른 실현이다. 실패해도 월 학습 전(rc 3)에 멈추므로 비용은 작다. §7 의 CUDA 공통 난수 진술도 미실측.
5. **데이터 지문 범위 확장**: 달 캐시 키 외에 시작일 · 신호일 · σ 표 · h 표 · 짝 상수를 넣었다 — 키에 없는 R 쪽 입력(σ 의 252일 종가 · 순열 시드)이 바뀌면 같은 이름에 다른 내용이 되는 것을 시험이 드러냈다(가드는 멈췄지만 이름이 바뀌는 쪽이 맞다).
6. **diag 열 이름 `cache_key`**(지시문 '데이터 도장' 계산용) — `key` 는 `data.table(key=)` 인자와 부딪혀 R 쪽에서 오작동한다.
7. **σ 수익의 정의**: 엔진 격자의 연속 거래일 1일 로그수익(전날 또는 당일 종가가 없으면 그날 수익 NA · 공백을 건너뛰는 다일 수익 없음). 팩터 DB D03_RealVol 은 단순 수익(Ret)을 쓴다 — 설계 문구('일 로그수익')를 따랐다.
8. **σ · h 결측 처리**: 열쇠 유효 종목의 자기 s 다중집합만 재배정 · 결측 종목은 그날 s 전체 중앙값 → 결측이 있는 날은 주변분포가 정확히 같지는 않다.
9. **h 의 창** = 학습 패널 `.P`(적격일 행만)에서 di ∈ [p − 252, p − 1] — '252 관측'이 아니라 '252 거래일 창 안의 적격일 관측'. lab_i ≤ u 이므로 실질 상단 = u − 5. 분위 = R `quantile(type = 7)`.
10. **V1 거부 몫의 기준 집합** = 엔진 적격 집합 U_d(셀 엔진 유동성 · 유니버스 필터 전). 최종 후보 안의 거부 비율은 20% 와 다를 수 있다(진단 기록 대상).
11. **예측표 쓰기 시점**: 엔진이 실제로 돌 때만 쓴다. 셀 기저 캐시가 적중하면 엔진이 돌지 않으므로 그 칸 로그에는 `[DT qpred]` 줄이 없다 — 평가는 같은 이름(CODE_VERSION md5 + 지문)의 파일 또는 첫 실행 로그를 쓴다.
12. **패널 삭제**는 성공 종료 때만(도중 실패 = 48시간 정리에 맡김).
13. **정적 PIT 검사기의 사각**: .R 파일 안 파이썬 문자열에는 R 패턴만 적용된다(PY_* 미적용) — 이번에는 추출본을 .py 로 따로 검사했다. 검사기는 고치지 않았다(보고만).
14. **엔진 리허설의 워커 상한 사본**: CPU 경로에서 워커가 최대 31개(torch 적재 각 수백 MB)라 시험 사본만 `.N_WORKERS_CAP` 32→2(달별 결과는 워커 수 · 순서와 무관 — 원본 주석). 실제 엔진 파일은 그대로.
15. **로그 문구**: 원본 'adapted' 요약 줄과 DNN 요약 줄은 구역으로 바꿔 MSE 를 합성 pinball 로 고쳐 적었다. 원본 머리말(1~40행) · 셀 로그 정규식이 기대할 수 있는 문구(`발행 %d개월` 등)는 그대로다.
